# Работа с Codex и личный вклад

## Что выполнено с помощью Codex

- Выбор реализации на базе Sites / Vinext, React, TypeScript, D1 и Drizzle.
- Проектирование модели пространств, клиентов, сделок, задач и событий.
- Реализация интерфейса, серверного API, валидации и изоляции демоданных.
- Подготовка миграций и вымышленных данных.
- Написание и выполнение доступных проверок; результаты в `verification.md`.
- Подготовка README, архитектуры, сценария видео и материалов портфолио.

Автор портфолио пока **не должен** заявлять, что лично выполнял эти проверки: агент не может засвидетельствовать действия пользователя.

## Что проверить и настроить самостоятельно

Поставьте отметку только после реального выполнения.

- [ ] Запустить проект с чистой установкой зависимостей и новой локальной БД.
- [ ] Объяснить путь запроса от формы до D1 и место проверки `workspace_id`.
- [ ] Добавить клиента и сделку, изменить этап, закрыть и снова открыть сделку.
- [ ] Проверить выручку и конверсию вручную на 3–5 своих тестовых записях.
- [ ] Открыть два браузерных профиля и убедиться в изоляции песочниц.
- [ ] Проверить настоящий вход с ChatGPT в опубликованной версии.
- [ ] Проверить интерфейс на собственном телефоне и только клавиатурой.
- [ ] Разобрать один неуспешный запрос через Network в DevTools.
- [ ] Прочитать SQL-миграцию и объяснить каскад удаления клиента.
- [ ] Самостоятельно добавить небольшое изменение и написать подходящую проверку.
- [ ] Проверить историю Git, связать GitHub-репозиторий и увидеть успешный CI.
- [ ] Пересказать ограничения MVP: роли, конкуренция изменений, квоты, очистка демо.

## Как описать вклад после проверки

«Я спроектировал сценарий CRM и управлял разработкой с Codex: уточнял требования, оценивал решения, проверял код и поведение продукта. Codex помог с реализацией и тестами. Самостоятельно я [укажите только выполненные пункты]. Могу объяснить авторизацию, изоляцию данных и расчёт показателей».

Хороший пример для собеседования — показать конкретную ошибку, тест, который её обнаружил, и исправление. В этом проекте можно разобрать ограничение D1 на параметры пакетной вставки, очистку даты закрытия при возврате сделки в работу и границы дня в московском часовом поясе.
